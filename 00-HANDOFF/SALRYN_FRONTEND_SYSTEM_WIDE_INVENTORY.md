## 1. Executive Summary of Frontend Surface Area

The Salryn POS web frontend ([`src/Salryn.App.Web`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/package.json)) is a React 19 + TypeScript 5.8 + Tailwind CSS 3.4 + TanStack Query v5 single-page application mounted by [`main.tsx`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/main.tsx#L1-L20) and orchestrated by [`App.tsx`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L1-L234).

### 1.1 Architectural Characteristics Verified from Source
1. **Dual-Entry Runtime Split ([`App.tsx:24-26`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L24-L26), [`lanEntry.ts:12-27`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/utils/lanEntry.ts#L12-L27))**:
   - When accessed over a loopback hostname (`localhost`, `127.0.0.1`, `127.*`, `::1`), [`App()`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L24) renders [`ConsoleApp`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L136) (the Host PC operator/owner application).
   - When accessed over any non-loopback hostname (e.g. a LAN IP `192.168.x.x` or `*.localhost`), [`App()`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L24) renders [`RemoteClientApp`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L28) (the LAN Terminal client flow).
2. **State-Driven Routing Without URL Synchronization ([`App.tsx:140`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L140), [`navigation.ts:1-60`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/navigation.ts#L1-L60))**:
   - There is no URL router (`react-router` is not installed). Host navigation is stored in `const [currentPage, setCurrentPage] = useState<AppPage>("dashboard")`.
   - Clicking sidebar items in [`AppShell.tsx`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/components/AppShell.tsx#L146-L152) invokes `onNavigate(item.page)` (`setCurrentPage`), which **does not push browser history state** or update `window.location`. Only cross-page drilldowns in [`OwnerReportsPage.tsx`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/pages/OwnerReportsPage.tsx) (`onOpenSales` / `onOpenReceivables` in [`App.tsx:184-195`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L184-L195)) call `window.history.pushState`.

## 3. Detailed Screen-by-Screen Audit Breakdown

### 3.1 Startup, Licensing, Bootstrap & Authentication Gates (S01–S04)

#### S01 — Startup Loading & Unavailable Gate ([`App.tsx:165-167`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L165-L167), [`App.tsx:199-220`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L199-L220))
- **Primary User Goal**: Understand whether the local Salryn Host service is starting up or requires recovery.
- **Critical Data**: Bootstrap status, session state, and Host license state.
- **States & Recovery**:
  - **Loading**: Dark slate background (`bg-slate-950`) with `"Starting Salryn POS..."`.
  - **Unavailable / Error**: Displays `"Salryn POS unavailable"` and a `"Try again"` button.
- **Audited Defect (P1)**: In [`App.tsx:166`](file:///C:/Salryn-Antigravity/src/Salryn.App.Web/src/App.tsx#L166), the `"Try again"` callback runs:
  ```ts
  void refreshBootstrapStatus();
  void licenseStatusQuery.refetch();
  ```
  It **omits `void sessionQuery.refetch()`**. If `sessionQuery.isError` was the transient failure that triggered the Unavailable gate, clicking `"Try again"` never re-fetches `/api/session`, leaving the operator permanently stuck until they manually refresh the browser (`F5`).
