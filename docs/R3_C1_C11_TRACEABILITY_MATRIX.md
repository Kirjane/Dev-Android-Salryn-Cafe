# Salryn Cafe R3 — Donor-to-Dev-to-R3 C1–C11 Traceability Matrix

This document records the authoritative functional, endpoint, RBAC permission, durable-intent, and executable verification traceability across the unified production R3 application (`/cafe/r3` & `/cafe/r3/*`), the Dev Host kernel (`Salryn.Api.Local`, `Salryn.Infrastructure`, `Salryn.Sync.Central.Server`), and the exact donor Program C architecture (`4241ea1e` — `00-QA/CAFE_YZA_PROGRAM_C_DAT_MATRIX.md` and `02-ARCHITECTURE/CAFE_YZA_C1..C11*.md`).

## Architecture & Installed Product Entry Point

- **Installed Product Entry Point:** `installer/SalrynCafeSetup.iss` launches `Salryn.Desktop.WebView.exe` → `DevHostConfig.DefaultInstalledWebUrl` resolves to `http://127.0.0.1:5399/cafe/r3` (the unified production R3 application), preserving `LocalWebOriginPolicy` loopback-only restrictions (`127.0.0.1:5399`, `localhost:5399`, dev `:5173`; retail ports `5299`/`5387`, external URLs, `file://`, `https://`, `data:`, `javascript:` remain blocked).
- **Preserved Legacy & Recovery Surfaces:** `/cafe/` (legacy Cashier Workstation), `/cafe/orders`, `/cafe/kitchen`, `/cafe/backoffice` (legacy Backoffice), and isolated `/cafe/central` (Central Owner Console) remain intact on the same loopback origin and verified by `apps/cafe-web/e2e/run-cafe-e2e.mjs` (zero-mock bundle guard + 11/11 E2E checks).
- **Host Startup Gate (Fail-Closed):** `GET /api/license/status` (`isLicenseActiveForBootstrap`) → `GET /api/bootstrap/status` (`POST /api/bootstrap/first-admin`) → `GET /api/session` (`POST /api/auth/login`) → `GET /api/system/identity` (fails closed `null` on error; binds `hostIdentityKey` + `actorUserId` for all v2 durable pending intents).
- **Durable Pending-Intent Authority (`apps/cafe-web/src/r3/live/durableIntent.ts`):** Persists v2 records (`salryn.cafe.r3.pending.<scope>.v2`) bound to `{ hostIdentityKey, actorUserId, intentId, ownerTabId }`, enforces cross-tab single-writer exclusion via Web Locks API + compare-owner `localStorage` leases, fences legacy pre-upgrade `.v1` keys fail-closed until Host ledger audit, fails closed before HTTP dispatch on storage failure, blocks cross-actor/cross-Host replay or discard, and preserves the unresolved fence on ANY retry failure (`401`/`403`/`400`/`404`/`409`/`422`/`ERR_IDEMPOTENCY_CONFLICT`) after an uncertain outcome.
